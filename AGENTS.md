# WebSynth

## Где менять код

- `src/app/main.tsx` запускает приложение.
- `src/pages/rack/ui` собирает экран проекта, каталог, диалоги и оболочку окна параметров.
- `src/widgets/rack-canvas` владеет React Flow, стилями холста, отображением узлов и кабелей, масштабом, выделением, перетаскиванием и горячими клавишами графа. Виджет получает патч и команды через публичный компонент `RackCanvas`.
- `src/pages/rack/model` владеет активным проектом, командами редактора, undo/redo, автосохранением и синхронизацией с аудиодвижком.
- `src/pages/rack/api/project-library.ts` читает и сохраняет библиотеку в IndexedDB. `src/pages/rack/lib` содержит адаптеры браузера для Web Audio, Web MIDI и скачивания JSON.
- `src/entities/audio-module/modules/<имя>` содержит весь код конкретного аудиомодуля. В `definition.ts` находятся порты, настройки и описание узла, в `controls.tsx` — панель параметров, в `runtime.ts` — специальная звуковая или MIDI-логика, в `styles.css` — собственные стили, если они нужны. Начинай изменение виджета с этой папки.
- `src/entities/project/model/patch.ts` содержит сериализуемую модель проекта и патча и операции графа. `project-json.ts` отвечает за формат JSON и проверку импортируемых данных.

Перед изменением найди существующего владельца и его контракт. Экранный сценарий добавляй в `pages/rack`, взаимодействие с холстом — в `widgets/rack-canvas`, общее правило проекта или графа — в `entities/project/model`. Совместимость сигналов меняется в модели графа, обработка горячей клавиши графа — в виджете, управление историей операции — в модели страницы.

## Как расширять архитектуру

1. Новый экран размещай в отдельном слайсе `pages`. Оставляй код, используемый одним экраном, рядом с его потребителями.
2. Выделяй `features` для самостоятельного пользовательского действия с понятным контрактом, когда его используют разные потребители. Выделяй `widgets` для самостоятельного составного блока интерфейса, который нужен нескольким потребителям.
3. Новый слайс `entities` вводи для предметного понятия с самостоятельными инвариантами и контрактом. Если одна логика нужна нескольким слайсам, определи общего владельца по смыслу и размести контракт ниже потребителей.
4. Добавляй сегмент `shared` для общей инфраструктуры или UI без знаний о патчах, проектах и редакторе. Создавай слои и сегменты вместе с кодом, которому они нужны.

## Импорты

Порядок слоёв сверху вниз — `app → pages → widgets → features → entities → shared`. Слайс может импортировать себя и нижележащие слои. В `app` и `shared` сегменты одного слоя могут взаимодействовать. Связь между сущностями проекта и модуля выражена через `entities/audio-module/@x/project.ts`. Этот контракт предназначен для `entities/project` и содержит только данные и чистые операции. Другие импорты между соседними слайсами проверка отклоняет.

За пределами слайса используй его `index.ts`, внутри — прямые относительные импорты. Для будущих сегментов `shared` используй отдельные публичные точки входа. Экспортируй именованно только те операции и типы, которые нужны внешним потребителям. Это правило применяется также к типам, реэкспортам и динамическим импортам.

- Из `src/pages/rack/model/use-rack.ts` допустим `import { connect } from '../../../entities/project/index.ts'`.
- Из `src/entities/project/model/project-json.ts` допустим внутренний `import { canConnect } from './patch.ts'`.
- Из `src/entities/project/model/patch.ts` допустим `import { ports } from '../../audio-module/@x/project.ts'`.
- Из `src/pages/rack/model/use-rack.ts` запрещён `import { connect } from '../../../entities/project/model/patch.ts'`.

## Аудиомодули и данные

При добавлении модуля создай папку рядом с остальными типами. Зарегистрируй определение в `model/catalog.ts`, а панель и при необходимости фабрику runtime — в `browser-registry.ts` того же слайса. Холст строит порты из определения, движок соединяет runtime через общий контракт. Сохраняй ID существующих портов. При удалении runtime освобождай аудиоресурсы и обработчики. Web Audio, Web MIDI и DOM принадлежат браузерному runtime. В проект записываются сериализуемые данные и идентификаторы. Тесты на Node.js используют чистый вход `entities/audio-module/model.ts`. Подробный порядок описан в [WIDGET_DEVELOPMENT.md](WIDGET_DEVELOPMENT.md).

Текущий формат JSON использует `schemaVersion: 1`. IndexedDB использует базу `websynth` версии `1`, хранилище `library` и ключ `state`. При изменении сериализуемых полей проверяй чтение старых проектов, рабочего патча и всех именованных версий. Для несовместимого изменения формата предусмотрены повышение версии затронутого формата и миграция его данных.

## Проверки

Перед завершением запускай `npm test`, `npm run check:architecture` и `npm run build`. Проверяй затронутый сценарий в настольном Chrome. Для графа проверь маршрутизацию и undo/redo, для хранения — загрузку и повторное открытие проекта, для звука и MIDI — работу изменённой цепочки. Если владелец кода переместился, обнови пути в документации.
